# Codebase

How the repo is structured and how to run the scripts. Project context and data are in [PROJECT.md](./PROJECT.md).

---

## Current status (Mar 2026)

- Core nutrition labeling flow is active: lookup parsing + CSV labeling are implemented and runnable.
- LLM-to-SQL is implemented with a shared service module + CLI + Gradio UI.
- Input dataset for DB build is `data/cleaned_dataset_with_labels.csv`; persisted output DB is `database/nutrition_data.duckdb` with table `nutrition_data`.
- Batch trace outputs are available under `outputs/llm_to_sql_trace_*.json`.
- `environment.yml` has been removed; dependency setup is now via `requirements.txt` in the active `eda` conda environment.

## Scripts

### 1. Parse PDFs → lookup CSVs

**Script:** `scripts/parse_assessment_pdfs.py`

Reads the three assessment PDFs in `data/` and writes CSV lookups to `data/processed/`. Run once (or when PDFs change).

```bash
python scripts/parse_assessment_pdfs.py
```

**Outputs:** `data/processed/stunting_lookup.csv`, `underweight_lookup.csv`, `wasting_lookup.csv`.

---

### 2. Add labels to cleaned CSV (file output)

**Script:** `scripts/add_nutrition_labels.py`

Reads `data/cleaned_dataset.csv`, applies lookup-based nutrition labeling logic from `src/nutrition_labels.py` for Feb/Mar/Apr, and writes a labeled wide CSV.

```bash
python scripts/add_nutrition_labels.py
```

**Defaults:**
- input: `data/cleaned_dataset.csv`
- output: `data/cleaned_dataset_with_labels.csv`

**Options:** `--input` (input CSV path), `--output` (output CSV path).

Progress is shown with `tqdm` (month-level and row-level bars).

---

### 3. Build persistent DuckDB

**Script:** `scripts/build_nutrition_db.py`

Builds and saves `database/nutrition_data.duckdb` from `data/cleaned_dataset_with_labels.csv`.
It normalizes bool-like `*_is_*` fields to numeric `0/1` and writes table `nutrition_data`.

```bash
source ~/.bashrc
conda activate eda
python scripts/build_nutrition_db.py --csv data/cleaned_dataset_with_labels.csv --db database/nutrition_data.duckdb
```

**Options:** `--csv`, `--db`, `--table`.

---

### 4. LLM-to-SQL query (CLI)

**Script:** `scripts/llm_to_sql.py`

Runs natural-language nutrition analytics over persisted DuckDB (`database/nutrition_data.duckdb`) via the shared service in `src/nutrition_sql/service.py`. Requires `OPENAI_API_KEY` (e.g. in `.env`).

```bash
source ~/.bashrc
conda activate eda
python scripts/llm_to_sql.py --db database/nutrition_data.duckdb --top-k 5 "Top 5 districts by SAM reduction from Feb to Mar"
```

**Options:** `--db`, `--model`, `--temperature`, `--top-k`, `--output-dir`, `--queries-file`, `--verified-sql-file`.

**Notes:**
- Prompt includes business rules for SAM and missing Hb behavior.
- Build step is one-time (or rerun when source CSV changes); query step reuses saved DB.
- You may see a benign warning from `duckdb-engine` about index reflection.
- Template routing is removed; all SQL is generated by the LLM.
- Batch verification compares generated SQL results against `data/queries /queries_verified.sql` with structured/tolerant result comparison.

---

### 5. Gradio app (interactive chat)

**Script:** `apps/gradio_app.py`

Launches a minimal chat-first UI for interactive NL querying over `nutrition_data`.
The app currently displays:
- chat answer (with compact result preview)
- generated SQL panel
- raw SQL output panel

```bash
source ~/.bashrc
conda activate eda
python apps/gradio_app.py
```

For a temporary public link:

```bash
GRADIO_SHARE=true python apps/gradio_app.py
```

## Dependencies

- **PDF parsing / CSV labeling:** `pandas`, `PyPDF2`, `tqdm` (see `requirements.txt`).
- **Labeling script:** `tqdm` for progress bars.
- **LLM-to-SQL / UI:** `langchain`, `langchain-community`, `langchain-openai`, `duckdb-engine`, `sqlalchemy<2`, `openai`, `python-dotenv`, `gradio`.

Install with:

```bash
source ~/.bashrc
conda activate eda
pip install -r requirements.txt
```


## OOM troubleshooting

- Ensure lookups are generated first: `python scripts/parse_assessment_pdfs.py`.
- `scripts/add_nutrition_labels.py` loads the full CSV into memory; run on a machine with enough RAM.
